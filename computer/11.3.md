# 11.3 Mosaic 與 Netscape：瀏覽器大戰的開端

## 瀏覽器之前的慘狀

在 Mosaic 與 Netscape 登場之前，瀏覽網頁是一項極其小眾的活動。早期的瀏覽器僅支援文字與基本圖片，介面極其枯燥，更何況談何色彩、動畫或多媒體。使用者必須透過命令列輸入 URL，看到的不過是一片碼字與極少數的標記。

更糟糕的是，各個瀏覽器之間缺乏相容性。在不同的瀏覽器中，相同的 HTML 文件可能呈現出完全不同的版本，這對於希望廣大受眾瀏覽的網頁設計者來說，是一場噩夢。

## Mosaic：讓圖像見光

1993年，伊利諾伊大學香檳分校的國家超級運算應用中心（NCSA）釋出了 **Mosaic**。這款瀏覽器由 Mark Andreeson 率領團隊開發，成了轉折點。

Mosaic 的革新在於：它是首款普及化的圖形化瀏覽器。它不僅支援文字，還能以 WYSIWYG（所見即所得）的方式顯示圖片。這意味著，網頁設計者可以在文本中嵌入圖片，使用者看到的就是最終的視覺呈現，無需再透過連結下載後再查看。

Mosaic 另一個關鍵突破，在於其跨平台支援。它在 Unix、Windows 與 Macintosh 三大作業系統上都能運行，這在當時極其罕見。此外，Mosaic 也支援多種網路協定，不僅限於 HTTP，還包括 FTP、NNTP（網路新聞傳輸協定）等。這使得使用者能夠在同一個介面內，瀏覽網頁、下載檔案、閱讀新聞，極大地提升了使用便利性。

Mosaic 的成功，證明了「圖形化介面」是大眾所願意接受的。它的用戶界面極其直觀：地址列在頂部、導航按鈕（前進、後退、重新整理）固定於工具列，書籤功能易於存取。這種設計，成了後來所有瀏覽器的標準模板。

然而，Mosaic 作為開源項目，雖然廣受好評，但其發展受限於學術機構的資源。團隊成員逐漸離開，項目逐漸失去勢頭。這為商業化的進入開啟了大門。

## Netscape：將瀏覽器變成平台

1994年，Mosaic 的核心團隊（包含 Mark Andreeson）離開學術界，創辦了 **Netscape Communications Corporation**。他們推出了 **Netscape Navigator**，這款瀏覽器在 Mosaic 的基礎上，進行了深度的商業化與功能擴充。

Netscape Navigator 的亮點極多：

- **更快的渲染速度**：針對日益增長的網頁體積進行了優化，頁面載入更為流暢
- **內建功能**：除了瀏覽網頁，Netscape 還內建了郵件客戶端（通訊錄、郵件撰寫）、IRC 聊天工具與 HTML 編輯器。這標誌著瀏覽器不再僅僅是「看書」的工具，而開始成為「作業平台」
- **Java 的支援**：Netscape 早期引入了對 Java 小程式碼的支援，讓網頁能夠包含動態、互動的內容。雖然 Java 最後並未像預期那樣在瀏覽器中大行其道，但這段經驗為後來的 Ajax、WebAssembly 鋪平了道路
- **Cookie 的引入**：Netscape 於 1994年引入了 **Cookie** 概念，讓網站能夠在使用者的本地儲存狀態資訊。這使得購物車、個人化設定與廣告追蹤成為可能，雖然也隨之引發了隱私爭議

Netscape 的成功，直接啟動了「瀏覽器大戰」。微軟意識到瀏覽器的戰略價值，開始開發自己的瀏覽器—— **Internet Explorer**。隨後的幾年間，Netscape 与 Internet Explorer 展開了殊死搏鬥，市場份額劇烈易手，但最終消費者受益，因為瀏覽器功能日益豐富，價格（免費）不斷下降。

更有趣的是，Netscape 的商業模式也經歷了轉變。1998年，面對微軟的猛攻與營運困難，Netscape 將其原始碼開源，成立了 **Mozilla 基金會**。這項舉動，不僅拯救了瀏覽器核心技術的開放性，更間接啟動了 Firefox 專案，成為了多年後 Chrome 與 Edge 的重要競爭對手。

## 本章小結

- Mosaic 以其圖形化介面、跨平台支援與多協定整合，確立了瀏覽器的基本原型與用戶體驗典範
- Netscape Navigator 在 Mosaic 的基礎上，進行了商業化與功能延伸，將瀏覽器變成了具備郵件、聊天、編輯功能的作業平台
- 「瀏覽器大戰」間接推動了網頁技術的快速演進，最終促使網頁標準的規範化與開源社群的興起
- Mosaic 与 Netscape 的遺產，至今仍藏匿在現代瀏覽器的每一個角落：從標籤管理、標籤到安全機制，再到開源社群的營運模式

## 想一想

1. Mosaic 與 Netscape 的成功，歸因於圖形化介面的普及化與功能的豐富化。在今天的行動端應用與原生 App 盛行的背景下，瀏覽器作為「萬國公告欄」的角色是否仍然相關？還是已被 App 生態系邊緣化？

2. Mosaic 與 Navigator 的時期，引入了 Cookie 以支付狀態管理。 Cookie 隨後成為隱私爭議的焦點。現代的隱私法規（如 GDPR、CCPA）是如何應對 Cookie 與同類追蹤技術的？未來的替代方案（如隱私沙盒、FLoC）是否能在保護隱私的同時，維持廣告產業的營運需求？

3. 如果讓你設計下一代瀏覽器，考慮到 today 的 AI 生成內起、實時翻譯與隱私保護需求，你會如何重新構想地址列、標籤管理與隱私模式？是保留舊有概念進行演進，還是直接推翻重來？
