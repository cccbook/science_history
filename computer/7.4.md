# 7.4 1969 年貝爾實驗室的閣樓：湯普森、里奇與 Unix 的誕生

## 閣樓上的奇蹟

1969 年的秋天，貝爾實驗室的閣樓裡，正躋進著兩位年輕的研究員：肯·湯普森和丹尼斯·里奇。他們手中握有 DEC（數位設備公司）的 PDP-7 小型機，卻無計算機可用。更糟的是，貝爾實驗室原本支持的 Multics 系統已在 1969 年撤出，留下了一片荒涼。

湯普森和里奇並非因為手頭缺硬體而煉獨。他們深知，作業系統的缺失，正嚻礙著實驗室的研究效率。於是，他們決定動手建立一個屬於自己的系統。

## Unics 的早期階段

最初，這個系統僅僅是一個簡單的檔案管理程式。湯普森用組合語言編寫了基礎的磁碟讀寫例程，讓機器能夠儲存和檔案。然後，他們加入了一個簡殼層，讓使用者能夠透過命令與系統對話。

系統的名字起得很有諷刺意味。湯普森曾說：「我們把它叫 Unics，因為它是 Multics 的縮影——精簡、單純，卻意外地好用。」這個名字最終被縮寫為 Unix，這個名字隨著時間流傳，成為了科技界傳奇。

Unics 的早期版本極其精簡。它只有幾百行程式碼，卻包含了現代作業系統的雛形：
- **殼層**：提供命令列介面
- **檔案系統**：支援樹狀目錄結構
- **程序執行**：能夠載入並執行可執行檔案
- **殭滅處理**：當程式結束時，自動釋放資源

更神奇的是，Unics 具有極強的擴展性。由於其核心設計極其精簡，研究人員可以在不破壞底層的情況下，輕易地新增功能。比如，他們加入了 pipes（管道），讓一個程式的輸出可以即時讓下一個程式作為輸入。這個點子成為了 Unix 哲學的靈魂。

## 關鍵突破：C 語言的誕生

Unix 早期的缺陷在於：它是用組合語言寫成的。這意味著，若要在不同的硬體平台上移植 Unix，必須完全重寫所有程式碼。這對於研究人員而言，是一項不可接受的負擔。

於是，里奇決定構建一個新的程式語言，專門用來編寫作業系統。這個語言名為 **C**。C 語言的設計哲學極其聰明：
- 保留組合語言的效能與靈活性
- 提供高階語言的抽象層次
- 具有可移植性，能夠在不同架構上編譯

1972 年，C 語言問世。同時，里奇開始將 Unix 重寫成 C 語言。這是一個轉折點：以往的作業系統緊密綁定特定硬體，而 Unix 現在可以在任何支援 C 編譯器的機器上運轉。

C 語言與 Unix 的雙雙壯大，形成了難分難舍的共生關係。C 提供了 Unix 所需的移植性，而 Unix 則成了 C 語言最佳的應用平台。兩者共同，開啟了個人電腦革命的大門。

## Unix 的散佈與演進

Unix 的傳播速度出奇的快。1970 年代初，貝爾實驗室開始向學術機構和其他研究機構授權 Unix。由於源碼開放，加上 C 語言的移植性，Unix 被移植到了各種硬體平台上：

- 1975 年，Unix 被移植到 VAX minicomputer，性能提升了數個數量級
- 1980 年代初，Unix 成為了學術界的標準作業系統
- 1984 年，Andrew Tanenbaum 發布了 Minix，一個專為教育設計的 Unix 克隆版，直接啟動了林納斯·托瓦茲 開發 Linux 的念頭
- 1991 年，林納斯·托瓦茲 發布了 Linux Kernel，開啟了開源作業系統的新紀元

同時，Unix 也衍生出了許多分支：System V、BSD（Berkeley Software Distribution）等。每一個分支都在原本的基礎上，新增了特色與優化。

## 本章小結

- 1969 年，貝爾實驗室的閣樓上，湯普森和里奇基於 PDP-7，啟動了 Unix 的開發
- Unix 的核心哲學在於極簡主義：只實作必備功能，拒絕華而不實的特性
- 1972 年，里奇設計了 C 語言，並將 Unix 重寫成 C，實現了作業系統的極致移植性
- C 語言與 Unix 的雙雙壯大，形成了產業標準，影響了個人電腦革命
- Unix 的散佈與演進，直接啟動了 Linux、macOS 等後世作業系統的發展

## 想一想

1. Unix 的極簡主義哲學（「做好一件事」），在今天的微服務與大規模分散式系統時代，是否仍然相關？我們是該堅持極簡，還是該擴展功能？

2. C 語言與 Unix 的共生關係，是軟體歷史中最成功的合作夥伴關係之一。你認為什麼因素，讓這段關係能夠延續了半個世紀並且始終保持活力？

3. 如果今天重新設計一個類似 Unix 的作業系統，考慮到現代的容器化、雲端與安全需求，你會保留 C 語言與極簡主義嗎？或者選擇記憶體安全的語言（如 Rust）與微服務架構？
