# 8.2 推導：Big-O 符號的嚴格定義與漸進分析

## 數學符號的由來

Big-O 符號的數學淵源，可以追溯到 19世紀德國數學家約翰·博赫納（Paul Bachmann）。他在 1894 年的書籍 **Analytische Zahlentheorie**（解析數論）中，首次引入了 O（大O）與 Ω（大Omega）符號，用以描述數論函數的漸近行為。然而，在半個世紀後，高德納的推廣，才讓這些符號成為了演算法分析的標配。

## 嚴格定義：為什麼我們需要 O、Ω 與 Θ？

在討論演算法複雜度時，我們通常需要三種符號來完整描述演算法的性能表現：

- **Big-O（O）**：描述上界。如果 f(n) = O(g(n))，表示 f(n) 的成長速度不超過 g(n) 的某個常數倍。簡單來說，這是「最壞情況下的成長上限」。
- **Big-Omega（Ω）**：描述下界。如果 f(n) = Ω(g(n))，表示 f(n) 的成長速度至少不低於 g(n) 的某個常數倍。簡單來說，這是「最佳情況下的成長下限」。
- **Big-Theta（Θ）**：描述緊致界。如果 f(n) = Θ(g(n))，同時滿足 f(n) = O(g(n)) 且 f(n) = Ω(g(n))。這表示 f(n) 與 g(n) 成長速度相同，是「精確的成長界」。

讓我們透過一個具體例子來理解。假設我們有一個簡單的迴圈程式片段：

```python
total = 0
for i in range(n):
    total += i
```

這段程式包含兩個部分：變數初始化（常數時間）與迴圈執行（n 次）。我們可以表示其執行次數為：

$$f(n) = c_1 + c_2 \times n$$

其中 $c_1$ 與 $c_2$ 為常數。根據 Big-O 的定義，我們可以說：

$$f(n) = O(n)$$

因為存在常數 c = $c_2$ + 1，當 n 足夠大時，$c_1 + c_2 \times n \leq (c_2 + 1) \times n$。同樣地，我們也可以說 $f(n) = \Omega(n)$，因為存在常數 c = $c_2$，當 n 足夠大時，$c_1 + c_2 \times n \geq c_2 \times n$。

由於同時滿足上下界，我們更進一步可以說：

$$f(n) = \Theta(n)$$

這表示這個迴圈的執行時間，與 n 成正比——這是一個精確的描述。

## 漸進分析的三大原則

漸進分析不在於計算精確的運行次數，而在於關注影響效能的「主導項」。這裡有三個核心原則：

1. **棄掉常數項**：無論常數多大，當 n 足夠大時，常數項對成長速度的影響可以忽略不計。比如 $100n + 1000$，我們說是 $O(n)$，而非 $O(1000n + 1000)$。

2. **棄掉非主導項**：對於 $n^2 + 5n + 100$，當 n 趨向無限大時，$n^2$ 的成長速度遠超 $5n$ 與 $100$，我們棄掉後者，只保留 $n^2$，說是 $O(n^2)$。

3. **只有最壞情況（或平均情況）才計算**：在評估演算法時，我們通常關注「最壞情況」的時間複雜度。因為這能保證我們的系統在任何情況下都不會超過預期的時間界限。

以排序演算法為例：冒泡排序在最好的情況下（已排序的陣列），時間複雜度可能接近 $O(n)$；但在最壞的情況下（逆序陣列），時間複雜度為 $O(n^2)$。我們通常引用後者，因為它能保證排序的上限。

## 常見複雜度階級的排序

在漸進分析中，我們常見以下幾種複雜度階級，按成長速度由慢到快排列：

| 符號 | 名稱 | 典型例子 |
|------|------|----------|
| O(1) | 常數階 | 陣列隨機存取、常數運算 |
| O(log n) | 對數階 | 二分搜尋、平衡樹操作 |
| O(n) | 線性階 | 迴遍歷陣列、簡單搜尋 |
| O(n log n) | 線性對數階 | 快速排序、合並排序 |
| O(n²) | 平方階 | 冒泡排序、插入排序、雙重迴圈 |
| O(2ⁿ) | 指數階 | 遞歸全搜尋、塔羅問題 |
| O(n!) | 階乘階 | travelling salesman 問題的暴力搜尋 |

這些階級讓我們能夠一眼看出，當問題規模 n 增大時，不同演算法的相對效能差異。例如，當 n = 1,000,000 時，$O(n \log n)$ 約需 20,000,000 次運算，而 $O(n^2)$ 則需要 1,000,000,000,000 次運算——差異高達 50,000 倍。

## 本章小結

- Big-O、Big-Omega、Big-Theta 三種符號，分別描述演算法的上界、下界與緊致界
- 漸進分析棄掉常數項與非主導項，關注問題規模 n 趨向無限時的成長速度
- 常見複雜度階級從 O(1) 到 O(n!)，清楚展示了問題規模變大時的效能差異
- 這套數學框架，讓我們能夠跳脫機器依賴的細節，專注於演算法本質的效能特性
