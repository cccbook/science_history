# 6.2 組合語言的誕生：把十六進位讉成助記符

## 機器碼的噩夢

在高階程式語言（如 Fortran、COBOL）出現之前，程式設計師必須直接與機器對話。他們寫下由 0 和 1 組成的機器碼，或者是十六進位數字，直接對應電腦的開關狀態。這項工作極其枯燥且易誤。

以一個簡單的加法運算為例：在機器碼中，可能需要寫下類似「1011 0010 0000 1101」這樣的串列。為了記住每一個位元的意義，程式員必須時刻記憶電腦的指令集架構。一旦誤打一個數字，或者對應的位元錯誤，整個程式就可能報錯，甚至損壞硬體。

更糟糕的是，不同的電腦架構有不同的機器碼。一個在 Intel 電腦上寫好的程式，搬到 Motorola 或 ARM 電腦上，必須完全重寫。這種缺乏移植性的狀況，極大地限制了軟體的散佈和重用。

## 葛麗絲·霍普的餘威：助記符的概念

雖然葛麗絲·霍普主導開發了高階語言，但組合語言（Assembly Language）的概念是同時代其他研究人員提出的。組合語言的核心思想是：使用易記的助記符，對應機器碼的十六進位數字。

最早的組合語言出現在 1950 年代末。它們不需要像高階語言那麼複雜的編譯過程，只需要一個簡單的「匯編器」（Assembler），將助記符轉換成對應的機器碼。

例如，與其記憶「1011 0010 0000 1101」，程式員可以寫下：
```
LOAD A, VALUE1
ADD B, VALUE2
STORE RESULT
```

這些助記符對應特定的機器碼操作碼。匯編器負責將其轉換成電腦能理解的機器碼。

## 組合語言的優勢與局限

組合語言相對機器碼有顯著優勢：
- **可讀性**：助記符如 LOAD、ADD、STORE 比 0 和 1 的串列容易記憶
- **可移植性**：雖然仍與特定架構綁定，但比機器碼靈活許多
- **效率**：程式員仍能直接控制硬體，達成極致的運算效能

然而，組合語言也有明顯的局限：
- **抽象層次有限**：程式員仍必須瞭解底層的記憶體管理和寄存器使用
- **開發速度慢**：相比高階語言，用組合語言寫程式仍然非常耗時
- **易誤**：即使有助記符，一個錯誤的記憶體位址，仍可能導致程式崩潰

## FORTRAN 的衝擊

1957年，IBM 發布了 Fortran (FORmula TRANslation)，這是世界上第一個廣泛使用的高階程式語言。Fortran 的出現，標誌著組合語言開始面臨挑戰。

Fortran 讓程式員不需要關心記憶體位址或機器碼細節。他們只需要關注數學公式的邏輯：
```
DO 10 I = 1, 100
  X = X + A(I) * B(I)
10 CONTINUE
```

雖然 Fortran 生成的機器碼可能不如精心編寫的組合語言那麼極致優化，但它的生產力優勢巨大。更重要的是，Fortran 程式可以在不同的電腦架構上移植，只需要重新編譯。

## 組合語言的永續價值

儘管高階語言佔據主流，組合語言並未被淘汰。相反，它在特定領域依然不可或缺：

1. **作業系統開發**：Windows、Linux 的核心部分，仍大量使用組合語言撰寫，因為需要直接操作硬體
2. **嵌入式系統**：微控制器、汽車電子、航空電子，對效能和記憶體有極嚴格要求
3. **逆向工程與安全研究**：分析軟體漏洞、惡意程式碼時，必須讀懂組合語言
4. **編譯器實作**：構建新的程式語言時，匯編器是必不可少的組件

## 本章小結

- 組合語言使用助記符替代機器碼的十六進位，提高了程式碼的可讀性
- 匯編器負責將助記符轉換成機器碼，是程式語言轉換的橋梁
- Fortran 的出現，標誌著高階語言開始挑戰組合語言的統治地位
- 組合語言在作業系統、嵌入系統、安全研究等領域仍保持著不可替代的地位
- 程式語言的演進，是一條從低效但可控，到高效但抽象的漸進之路
