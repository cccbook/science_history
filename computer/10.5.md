# 10.5 網域系統（DNS）：給每一座數字孤島取名字

## 數字與名字：互聯網的記憶難題

在互聯網的早期，每台連線的設備都擁有唯一的 **IP 位址**。IP 位址是一串數字，如「192.168.1.1」或「202.108.22.5」。人類的大腦極難記住這些數字組合，更何況還要記住數以萬計的設備位址。

更糟糕的是，IP 位址有時會變動（如撥號連線、動態分配的 DHCP 位址）。如果每次位址變動，所有的書籤、連線紀錄都必須即時更新，這對早期的網路管理者來說，是一項不可逾越的負擔。

因此，1983年， **ポール·莫倫**（Paul Mockapetris）設計了 **DNS**（Domain Name System，域名系統）。這是一個分散式數據庫系統，將人類友善的 **域名**（如 www.example.com）轉換為機器可讀的 **IP 位址**。DNS 就像是互聯網的「電話簿」，讓我們無需背記一串串數字，即可輕鬆連線至任何網站。

## DNS 的運作機制

DNS 的架構極其巧妙，採用了「分散式」與「階層式」相結合的方式。當使用者在瀏覽器中輸入域名時，以下流程會發生：

1. **本地查詢**：電腦首先檢查本地的 hosts 檔案或快取，看是否已知該域名對應的 IP 位址
2. **遞歸查詢**：若本地無資訊，電腦會連絡 **本地 DNS 解析器**（通常由 ISP 提供）。這個解析器會接連詢問下列權威伺服器：
   - **根伺服器**（Root Server）：全球共有 13 組根伺服器（實際上透過 anycast 分散），它們知道各トップ級域名（如 .com、.org、.net）的位址
   - **權威伺服器**：負責特定域名的最終解析，返回該域名對應的 IP 位址
3. **緩存**：每一步查詢的結果，都會被暫時緩存在本地或 ISP 的伺服器上，以便下次查詢時直接返回，減少延遲

整個過程對使用者透明，僅耗數毫秒。更神奇的是，DNS 設計了 **TTL（存留時間）** 欄位，指示 IP 位址的有效期限。一旦 TTL 過期，解析器必須重新查詢，確保位址變動時能夠即時傳遒。

## DNS 的結構級別

DNS 的階層結構如同一棵倒掛的樹：

- **根域名**（Root Domain）：表示為 `.`（點），是所有域名的源頭
- **頂級域名**（Top-Level Domain，TLD）：位於根域名之下，分為兩類
  - **國家コード TLD**（ccTLD）：如 `.tw`（台灣）、`.us`（美國）、`.jp`（日本）
  - **通用 TLD**（gTLD）：如 `.com`（商業）、`.org`（組織）、`.net（網路）**、`.edu（教育）**、`.gov（政府）**
- **第二級域名**：位於 TLD 之下，如 `example` 在 `.com` 之下
- **主機名**：位於第二級域名之下，如 `www` 在 `example` 之下

舉例來說，域名 `www.wikipedia.org` 的結構如下：

```
                 .
                /|\
               / | \
              /  |  \
          .tw .org .com
           |       |
          wikipedia www
               |
           Main Page
```

這種結構，不僅讓域名管理極其有條不紊，也允許不同組織獨立管理自己的子域名。

## DNS 的安全挑戰與演進

DNS 的成功，固然建立在易用性與分散式架構之上，但也隨之帶來了安全挑戰。最著名的，是 **DNS 劫持**（DNS Hijacking）與 **DNS 放大攻擊**（DNS Amplification Attack）。

- **DNS 劫持**：攻擊者竊取域名控制權，將域名解析至惡意伺服器，使用者嘗試連線至合法網站時，實則被導向詐欺網站
- **DNS 放大攻擊**：攻擊者利用 UDP 特性，偽造受害者的 IP 位址，向大量 DNS 伺服器發送查詢請求。由於回應封包遠大於查詢封包，攻擊者就能產生極大的流量洪峰，對目標伺服器進行阻斷服務

為了對抗這些威脅，DNS 極其演進了安全機制：

- **DNSSEC**（DNS Security Extensions）：引入數位簽章，確保 DNS 回應的完整性與來源真實性。使用者的電腦可以驗證域名解析是否被竄改
- **DNSCrypt**：在使用者的電腦與 DNS 解析器之間加密查詢過程，防止竊聽與偽造
- **DOH**（DNS over HTTPS）：將 DNS 查詢封裝於 HTTPS 協議中，利用加密技術防止 ISP 或 中間人竊取查詢紀錄

更有趣的是，隨著隱私意識的提昇，許多使用者開始轉向使用第三方 DNS 服務（如 Google DNS 8.8.8.8、Cloudflare 1.1.1.1），以替代 ISP 預設的 DNS，以獲得更快的速度與更好的隱私保護。

## 本章小結

- DNS（域名系統）將人類友善的域名轉換為機器可讀的 IP 位址，解決了人類記憶數字的難題
- DNS 採用分散式階層架構，包括根伺服器、TLD 伺服器與權威伺服器，實現了域名的分佈式管理
- DNS 的運作流程包含本地查詢、遞歸查詢與緩存，整體延遲極低，對使用者透明
- DNS 安全面臨劫持與放大攻擊等威脅，已透過 DNSSEC、加密協議等機制加以加強
- DNS 不僅是技術基礎設施，更成為了網路身份認同與品牌資產的重要載體
