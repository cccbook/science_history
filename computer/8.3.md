# 8.3 排序演算法的極限：從冒泡排序到快速排序

## 排序的本質

排序是程式設計中最基本也最常見的操作之一。給定一個無序的資料序列，我們希望將其重新排列為特定順序（通常是遞增或遞減）。看似簡單，實則蕴含著極深的數學結構與演算法挑戰。

在計算機科學的早期，排序問題引發了無數研究。最直觀的方法當然是「冒泡排序」——重複比對相鄰元素，若順序錯誤則交換位置。這個過程像泡泡上升一樣，故得名。

然而，冒泡排序有其明顯的短板。它的時間複雜度為 O(n²)，意味著當問題規模 n 翻倍時，所需的比較與交換次數會 quadruple（變成四倍）。在大規模資料面前，冒泡排序顯得舉步維艱。

## 插入排序與選擇排序

除了冒泡排序，兩種常見的 O(n²) 演算法還有插入排序與選擇排序。

- **插入排序**：類似撲克牌遊戲，將未排序的資料一張一張地插入到已排序區間的適當位置。它在 nearly sorted（幾乎已排序）的陣列上表現極佳，時間複雜度可降至 O(n)。這也是為什麼在實務中，許多高階排序演算法的「基底案例」，當資料量極小時，會切換為插入排序。

- **選擇排序**：每次從未排序區間選擇最小（或最大）元素，與未排序區間的首元素交換。它的優點在於移動次數極少（最多 n 次交換），但在比較次數上仍為 O(n²)。

儘管這些演算法在數學層面表現平平，但他們在特定情境下仍不可或缺。例如，插入排序的穩定性與 nearly sorted 陣列的優異表現，使其成為了更大排序演算法的重要組成部分。

## 突破極限：快速排序

1960 年，托尼·霍爾在貝爾實驗室，發明了 **快速排序**。這是有史以來影響力最 profound 的排序演算法之一。它的核心思想極其巧妙：「分而治之」。

快速排序的步驟極簡：

1. **選取基準**：從陣列中選取一個「基準」元素。通常有多種策略：選取第一個、最後一個、隨機，或是「中位數三點取中」
2. **分區**：將陣列重新排列，使得「基準」左側的元素均小於基準，右側的元素均大於基準。這步驟稱之為「分區」operation
3. **遞歸**：對「基準」左側與右側的子陣列，重複上述步驟。直到子陣列規模足夠小，直接使用插入排序即可

快速排序的時間複雜度平均情況為 O(n log n)，最壞情況為 O(n²)（當基準選取極不當，導致每次分區都極不平衡）。然而，在實務情況下，透過「隨機化基準」與「三點取中」，最壞情況發生的機率極低，使得快速排序成為了絕大多數情境下的首選。

## 其他演算法：合並排序與堆排序

除了快速排序，兩種其他 O(n log n) 的演算法也極具意義：

- **合並排序**：採用極分化策略。將陣列不斷對半切分，直到每個子陣列只有一個元素；然後還原過程中，合併兩個有序子陣列為一個有序陣列。它的優勢在於穩定——無論最好、最壞、平均情況，時間複雜度永遠為 O(n log n)。但它需要額外的 O(n) 空間來暫存合併過程。

- **堆排序**：利用二元堆積的資料結構。先將陣列轉換成堆結構，然後不斷提取堆頂（最大或最小元素），重新調整堆結構。它的優勢在於空間複雜度僅為 O(1)（原地排序），但常數項較大，實作速度不如快速排序快。

## 理論極限：O(n log n) 為下限

一個驚人之處在於：對於比較型排序（僅依賴比較元素大小的演算法），O(n log n) 是**理論下限**。

證明過程源自於決策樹模型。對於 n 個元素，所有可能的排列總數為 n!。決策樹的葉子節點總數必須至少為 n!，而二元樹的深度 d 滿足 2^d ≥ n!。根據斯特林公式，log₂(n!) ≈ n log₂ n - n log₂ e，故而 d = Ω(n log n)。

這意味著，任何僅依賴元素比較的排序演算法，其時間複雜度絕不能低於 Ω(n log n)。快速排序、合並排序與堆排序，均達到了這個下限（平均情況），因此它們被視為「最優比較型排序」。

## 特殊情境：非比較排序

然而，如果我們能夠利用元素的特殊性質，突破比較極限呢？

- **計數排序**：適合元素範圍有限、整數的情況。它不依賴比較，而是利用「索引作為鍵值」，時間複雜度可降至 O(n + k)，其中 k 為元素範圍大小。

- **基數排序**：先按個位排序，再按十位、百位...排序。適用於固定位數的整數或字串。時間複雜度為 O(d × (n + k))，其中 d 為位數。

這些非比較型排序演算法，在特定情境下能夠突破 O(n log n) 的界限，實現線性時間排序。這提醒我們，演算法的選擇必須視資料特性而定。

## 本章小結

- 冒泡排序、插入排序、選擇排序為 O(n²) 的演算法，適合小規模或 nearly sorted 的陣列
- 快速排序以分而治之策略，平均時間複雜度達到 O(n log n)，實作靈活，是工業界最常用的排序
- 合並排序與堆排序則分別在穩定性與空間複雜度上提供了不同的權衡
- 理論上，任何比較型排序的下限為 Ω(n log n)，非比較型演算法（如計數排序、基數排序）可在特定情境下達成 O(n) 的線性時間
- 排序演算法的選擇，需視資料規模、分佈特性、穩定性需求與空間限制綜合考量

## 想一想

1. 快速排序的平均情況為 O(n log n)，最壞情況為 O(n²)，但實務中幾乎從不出現最壞情況。這中間的「信任」基於什麼？我們該如何妥善選取基準，降低最壞風險？

2. 合並排序需要額外的 O(n) 空間，而堆排序與快速排序皆為原地排序（O(1) 額外空間）。在記憶體極度受限的環境（如嵌入式系統），我們該如何權衡時間與空間的取捨？

3. 非比較型排序（如計數排序）能夠突破 O(n log n) 的下限，但受限於元素範圍與資料類型。在今天的大數據與機器學習時代，我們是否仍有機會利用這些演算法？或者現代的資料特性，使得它們的適用場域越來越窄？
