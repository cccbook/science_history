# 8.5 戴克斯特拉（Dijkstra）與最短路徑：結構化程式設計的勝利

## 最短路徑問題的直覺

在日常生活中，我們經常需要尋找最短路徑：從家到辦公室、從城市 A 到城市 B、甚至是在地圖 App 中規劃行程。這個問題看似直觀，卻隱藏著數學上的深層結構。

最早期的圖論家之一，威廉·羅利（William Rowan Hamilton）在 19世紀研究了圖上的迴路問題。然而，真正系統化地解決「最短路徑」問題，歸功於埃哲·戴克斯特拉（Edsger W. Dijkstra，1930－2002）。

1959年，年僅 29 歲的戴克斯特拉，在思考如何展示第一台可編程的電動計算機（EMAC）時，發明了現在聞名世界的**戴克斯特拉算法**。他的目標極其單純：尋找一個演算法，能夠從單一起點，計算到圖中所有其他節點的最短路徑長度。

## 戴克斯特拉演算法的核心邏輯

戴克斯特拉演算法極其優雅，其核心邏輯可以概括為「貪婪選擇與漸進更新」：

1. **初始化**：將起點的距離設為 0，其餘所有節點的距離設為無限大；建立一個「未訪問」集合，包含所有節點
2. **選擇最短**：從「未訪問」集合中，選擇當前距離最短的節點作為「當前節點」
3. **更新鄰居**：對於「當前節點」的每個未訪問鄰居，計算經過當前節點到達該鄰居的總距離。若該距離小於此前記錄的距離，則更新鄰居的距離
4. **標記已訪問**：將「當前節點」從「未訪問」集合移除，標記為「已訪問」
5. **重複**：當所有節點均被訪問，或剩餘節點無法抵達時停止

以一個簡單的例子說明：假設我們要從節點 A 前往節點 C。圖的結構為 A → B (距離 5)， A → C (距離 10)， B → C (距離 2)。

- 初始時：dist(A) = 0，dist(B) = ∞，dist(C) = ∞
- 步驟 1：選擇 dist 最小的節點 A（距離 0），更新其鄰居：dist(B) = min(∞, 0+5) = 5，dist(C) = min(∞, 0+10) = 10
- 步驟 2：從未訪問集合移除 A，選擇 dist 最小的節點 B（距離 5），更新鄰居：dist(C) = min(10, 5+2) = 7
- 步驟 3：移除 B，選擇 dist 最小的節點 C（距離 7），結束

最終我們得到：從 A 到 C 的最短距離為 7（經由 B），而非直接的 10。

## 時間複雜度與優化

戴克斯特拉演算法的時間複雜度取決於優先佇列（Priority Queue）的實作：

- **鄰接表 + 二進位堆**：O((V + E) log V)，其中 V 為節點數、E 為邊數
- **鄰接矩陣**：O(V²)

在穩健的實作下，戴克斯特拉演算法不僅正確，而且極其高效。更有趣的是，它具有**非負邊權重**的限制：若圖中包含負邊權重，演算法可能產生錯誤。這就是為什麼，在有負邊的情況下，我們通常改用 **貝爾曼-福特演算法** 或 **Floyd-Warshall 演算法**。

## 戴克斯特拉的貢獻超越算法

戴克斯特拉的影響力遠不止這一個演算法。他是結構化程式設計的先驅，其思想貫穿了整個軟體工程：

- **層次抽象**：戴克斯特拉主張將問題分解為更小、更易管理的子問題。這正是現代軟體設計的核心原則——「分而治之」
- **正確性證明**：他極其重視程式的數學驗證。他的名言「Program testing can be used to show the presence of bugs, but never to show their absence」（程式測試只能顯示 bug 的存在，永不能證明其不存在）至今仍是軟體工程的金科玉律
- **程式語言設計**：戴克斯特拉參與了 ALGOL 60 的設計，並在其中提出了著名的 **Dijkstra 範式**，用以描述如何設計可靠的迴圈

更有趣的是，他對「程式正確性」的奉獻，啟動了程式驗證領域的研究。他的著作《程式的構造》被譽為經典，影響了無數以後代的程式設計師。

## 本章小結

- 戴克斯特拉演算法解決「單一源點最短路徑」問題，時間複雜度 O((V + E) log V) 或 O(V²)
- 其核心邏輯「貪婪選擇與漸進更新」，透過不斷選擇當前距離最短的節點，最終求得全局最短路徑
- 演算法僅適用於非負邊權重圖，負邊情況需改用其他演算法
- 戴克斯特拉不僅是算法創作者，更是結構化程式設計的先驅，其正確性思維影響了整個軟體工程
- 其名言「測試只能顯示 bug 的存在，不能證明其不存在」，成為了軟體工程的基石原則

## 想一想

1. 戴克斯特拉演算法僅適用於非負邊權重，若圖中包含負邊，我們通常改用貝爾曼-福特或 Floyd-Warshall。負邊為什麼會導致戴克斯特拉失效？負邊在現實世界的圖問題（如交通網絡）中常見嗎？
