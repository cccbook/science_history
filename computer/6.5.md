# 6.5 ALGOL 60 與 LISP：兩種截然不同的世界觀

## ALGOL 60：結構化程式設計的巔峰

1958年，國際計算機會議在巴黎舉行，首次發布了 **ALGOL 60**（ALGOrithmic Language 1960）。這是一個由歐美數學家和工程師共同設計的程式語言，被許多計算機科學家視為「歷史上最完美的程式語言」。

ALGOL 60 的設計哲學核心在於**結構化程式設計**。它引入了幾個革命性的概念：

- **有界迴圈**：引入 `for` 迴圈，強制要求迴圈變數有明確的起始和終止值，這使得程式邏輯更易追蹤和驗證
- **區塊結構**：程式碼可以被組織進「區塊」，每個區塊有自己的變數作用域，變數在區塊外不可見。這極大地減少了變數衝突和副作用
- **遞歸**：支援函數的遞歸呼叫，這是當時極其前衛的特性

ALGOL 60 的一個標誌性特性，是它的**語法定義使用了巴科斯-諾爾範式（BNF）**。這使得語言的規格極其精確，也為後續的語言定標設定了標準。

雖然 ALGOL 60 在商業應用上未能佔據主導地位（COBOL 和 FORTRAN 更適合商業數據處理和數值運算），但在學術界和語言研究領域，它卻產生了不可磨滅的影響。ALGOL 60 的後繼者 ALGOL 68 雖然更加雄心勃勃，但因為太過複雜，最終未能廣泛採用。不過，ALGOL 60 的基因流傳到了 Pascal、C 以及 Java 等後續語言中。

## LISP：函數式程式設計的啟源

同一年，1958 年，約翰·麥卡蒂在麻省理工學院，獨立開發了 **LISP**（LISt Processing）。LISP 是世界上第二個高階程式語言（僅次於 FORTRAN），但它的設計哲學與 FORTRAN 截然不同。

LISP 的核心靈感來源於數學邏輯和遞歸函數理論。它的獨特特徵包括：

- **一切皆列表**：LISP 的基本資料結構是「列表」。甚至程式碼本身，也是以列表形式表示的。這使得 LISP 具備極強的「程式即資料」能力
- **遞歸為本**：LISP 沒有傳統的迴圈結構，一切通過遞歸函數來實現。這與 ALGOL 60 的「有界迴圈」形成鮮明對比
- **動態型別**：變數類型在運行時決定，而非編譯時期。這提供了極大的靈活性，但也帶來了效能上的挑戰
- **符號運算**：LISP 天生適合處理符號和文字運算，成為了人工智能研究的基石

LISP 最驚人之處在於其「萬物為列表」的概念。一個 LISP 程式碼片段：
```
(+ 1 2 3)
```
不僅是可執行的程式，也可以被視為一個數值列表。這種雙重身份，讓 LISP 成為了最早的「元語言」，程式員可以編寫編譯器、解析器，就像編寫普通程式一樣。

## 兩種哲學的碰撞

ALGOL 60 與 LISP 的並存，代表了程式語言設計兩條截然不同的道路：

**ALGOL 60 的道路**：
- 強調結構、可預測性、效能
- 適合數值運算、科學計算、系統程式設計
- 影響了 C、Pascal、Simula（後來演變成 C++）

**LISP 的道路**：
- 強調靈活性、動態性、 meta-programming
- 適合人工智能、符號運算、快速原型開發
- 影響了Scheme、Common Lisp、Clojure 以及現代的函數式語言

這兩種世界觀的衝突與共存，塑造了整個世紀的程式語言演進。有趣的是，這兩種風格的界限越來越模糊。現代的 C++ 支援函數式特性（如 Lambda 運算式），而 LISP 的後繼者則引入了類型系統和編譯優化，以提升效能。

## 本章小結

- ALGOL 60 代表結構化程式設計的巔峰，強調程式的清晰度、可預測性和效能
- LISP 代表函數式程式設計的啟源，強調靈活性、動態性和「程式即資料」的能力
- ALGOL 60 影響了 C、Pascal 等Imperative（命令式）語言的後裔
- LISP 成為了人工智能領域的基石，影響了後世的許多函數式語言
- 兩種哲學的對話，豐富了程式語言的設計版圖，也提醒我們「沒有銀子子彈」，不同問題需要不同語言
