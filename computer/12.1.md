# 12.1 埃德加·科德（E. F. Codd）：關聯式模型（Relational Model）的數學美感

## 數據管理的亂局

在 1960 至 1970 年代初期，數據管理領域呈現出一片混亂的景象。各大企業與研究機構，各自開發了屬於自己的數據庫系統，採用著各式各樣的模型：網狀模型（Network Model）、階層模型（Hierarchical Model）、以及早期的實體模型。每一種模型都有其特定的優勢，卻也伴隨著沉重的限制。

例如，網狀模型雖然靈活，卻要求程式員必須預先規劃好所有的資料關聯；而階層模型則結構嚴謹，卻難以處理一對多、多對多的複雜關係。更糟糕的是，若要在不同的系統間遷移資料，必須進行極其繁瑣的轉換與重構。這種「廂房門門通，各自為政」的局面，極大地限制了企業的資料整合與分析能力。

## 科德的突破：關聯模型

1970年，IBM 的研究員 **埃德加·科德**（Edgar F. Codd）發表了里程碑式的論文《關聯式資料的數學基礎》。他指出，現有的數據庫模型過於依賖「物理存取路徑」，即程式員必須瞭解資料在硬碟上的儲存位置與連結方式。他提出了一種全新的觀點：將資料視為數學上的「關係」（Relation），即二維表格。

科德的關聯模型包含三大核心原則：

1. **一切皆關係**：資料庫中的所有資料，皆以二維表格形式表示。每一個表格（Relation）由行與列組成，行代表實體紀錄，列代表屬性。
2. **無順序**：表格的行與列順序無意義，僅靠主鍵與屬性名稱來識別。這意味著，使用者無需瞭解資料在硬碟上的實際排列，只需關注邏輯結構。
3. **獨立性**：應用程式與存儲結構分離。因為變更儲存結構（如調整索引、壓縮資料），不應影響應用程式的運作。這就是所謂的「邏輯與物理獨立性」。

更有趣的是，科德還提出了 **關聯代數**（Relational Algebra），一套類似集合論的運算符集合（如選擇、投影、聯結、交集、並集）。這套代數，讓使用者可以用數學式的方式描述查詢邏輯，而無需寫死巢狀的迴圈與條件判斷。這為後來的聲明式查詢語言奠定了理論基礎。

## 關聯代數的基本運算

關聯代數包含幾個最基本的運算，它們如同數學中的加、減、乘、除，但作用於關係（表格）上：

- **選擇（Selection，σ）**：從表格中挑選出滿足特定條件的行。如 `σ_年齡>30(員工表)`，挑選出年齡超過 30 的員工
- **投影（Projection，π）**：從表格中挑選出特定的欄位。如 `π_姓名, 年齡(員工表)`，只顯示員工的姓名與年齡
- **聯結（Join，▷）**：根據共同屬性，將兩個或多個表格合併。最常見的是「內聯結」，只保留兩個表格中匹配的行
- **交集（Intersection，∩）**：返回兩個表格中同時存在的行
- **並集（Union，∪）**：返回兩個表格中任一個存在的行（要求兩個表格結構一致）
- **除法（Division，÷）**：這是最複雛的運算，通常用於「屬於「所有」條件的查詢。如「哪些同學修修過了所有必修課」

這些運算的優雅之處在於：它們可以組合成更複雜的查詢式。例如，尋找「修過所有必修課的同學」，可以用除法直接表達；而若只能使用選擇、投影、聯結等基本運算，則需要編寫數十行巢狀的迴圈與條件判斷。科德的貢獻在於，他證明了任何關於資料的查詢，都可以轉化為關聯代數運算的組合。

## SQL 的誕生與標準化

雖然科德的論文在學術界轟動，卻在業界起初未獲得重視。直到 1970 年代末，ibm 的項目 **System R** 實驗證明了關聯模型的實踐可行。隨後， **SEQUEL**（Structured English Query Language，後簡化為 SQL）應運而生。

SQL 不僅實作了科德關聯代數中的核心運算，還加入了各種實用擴充：群組運算（GROUP BY、HAVING）、視圖（View）與授權（Grant、Revoke）。1986年，SQL 成為 ANSI 標準，1992年成為 ISO/IEC 標準。這標誌著關聯式資料庫進入了工業化、標準化的軌道。

至今，SQL 依然是最普及的資料庫查詢語言，支援著 MySQL、PostgreSQL、Oracle、SQL Server 等主流資料庫系統。雖然隨著 NoSQL、NewSQL 等新興技術的登場，SQL 的統治地位開始出現變動，但其核心語法與邏輯，仍然深植於資料工程師的血脈中。

## 關聯模型的永續價值

科德的關聯模型，之於資訊科學，猶如歐幾得幾何對於數學的貢獻。它不僅提供了一套資料組織與查詢的工具，更確立了一種「以數學邏輯為基礎」的思考方式。

即便在今天的大數據與 NoSQL 盛況下，關聯模型的靈魂——關注「實體間的關係、結構獨立性與聲明式查詢」——仍然深深影響著資料庫的設計理念。現代的 NewSQL 資料庫，試圖在保持關聯模型優勢（如 ACID 交易、強一致性）的同時，兼顧分散式架構的擴展性；而 ORM（物件關聯映射）工具如 Hibernate、Entity Framework，更是將物件導向程式語言與關聯資料庫之間的轉換層，進一步延續了科德理念的延伸。

更有趣的是，科德晚年致力於研究「高級關聯運算」（Advanced Relational Operations），試圖在維持關聯模型堅實基礎的同時，拓展其處理非結構化資料、空間資料與時序資料的能力。這些研究，預見了現代資料庫面臨的複雜挑戰，也展現了科德對領域前瞻的洞察。

## 本章小結

- 科德的關聯模型以「二維表格」為核心，打破了既有的網狀、階層模型的限制
- 關聯代數提供了一套數學化的查詢運算集合，證明了任何資料查詢都可轉化為運算組合
- SQL 的誕生與標準化，將科德的理論轉化為實務工具，成為了資料庫產業的國際標準
- 關聯模型的永續價值在於其數學邏輯的純潔性、結構獨立性與聲明式查詢的便利性
- 即便在 NoSQL 盛世，關聯模型的核心概念（關係、主鍵、獨立性）仍深植於資料庫設計之中

## 想一想

1. 科德的關聯模型強調「一切皆關係」，將一切資料視為二維表格。這種極簡化的假設，是否限制了其處理非結構化資料（如文本、影片、聲音）的能力？現代的資料庫是如何在關聯模型之上，擴展處理這些非結構化資料的？

2. SQL 標準雖然普及，但不同資料庫廠商（Oracle、MySQL、PostgreSQL）往往擴充了許多廠商專有的語法與函數。這中間的衝突，是如何在「標準相容」與「功能擴充」之間經營的？未來是否會出現一個真正跨平台的標準 SQL？

3. 在大數據與分散式環境下，傳統的關聯模型面臨 CAP 定理（一致性、可用性、分區容錯性的權衡）的挑戰。現代的 NewSQL 與 NewSQL 類資料庫，是如何在保持關聯模型優勢的同時，應對分散式架構的挑戰？
